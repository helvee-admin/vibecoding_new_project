# 项目诊断与信息架构指南

先读目标项目已有资料，再询问会改变这轮工作的信息。一次可把相关问题合并起来，用户已交代过的直接引用。事实标明来源，用户偏好标为选择，推荐标为判断。

## 先取得足以开始的信息

| 从何处判断 | 对本次初始化有用的信息 |
| --- | --- |
| 用户和目标 | 谁在什么情境下遇到什么问题，目前怎样解决，这个阶段最想验证什么。 |
| 现有证据 | 想法、访谈、原型观察、真实使用、付费分别有哪些证据。数据来自哪里，哪些判断仍是假设。 |
| 交付条件 | 已有资产和技术、目标环境、团队能力与时间、涉及的数据、预算或外部操作边界。 |
| 市场与招募 | 如何接触首批用户、是否选了地区或语言、已有渠道和反馈。渠道待选时保留为待验证项。 |
| 协作 | 现有文件放在哪里、谁确认决定、希望哪种方式沟通，当前哪些专业工作确实有人要做。 |

## 按当前问题决定深度

| 可观察到的情况 | 本轮足够的产出 | 何时值得补充 |
| --- | --- | --- |
| 有一个想法，暂时接触得到少量潜在用户 | 一个用户场景、最关键假设、一项验证和结果判据。需要找人时，市场推广可只准备招募对象、邀请草稿和反馈方式。 | 原型可以让人独立执行任务时，增加相应的交互说明和验收项。 |
| 有原型或首个可用版本，已有试用反馈 | 选一条真实任务，记录卡点、复现条件、一次改进和观察办法。小样本保留人数、原话和行为差异。 | 重复出现的卡点、有可信事件数据的关键步骤或要正式交付的版本，分别触发专项工作。 |
| 有真实使用数据，或面临具体推广投入取舍 | 只为当前问题定义口径、可比基线及下一步实验。需要评估花费时先查支出及可归因结果。 | 根据观察窗口、样本量和决策成本选择分析深度。商业结果未知可以保持未知。 |

以上情形可以并存。例如已发布的内部工具可能只需要工程、QA 和用户反馈。一个尚无收入的消费产品也可以为了招募访谈对象先启用市场推广。

## 选择领域与对齐

从产品、设计、工程、QA、发布、市场推广中选有实际任务的领域。营销招募可以很早开始，发布准备可以很晚才需要。一个人可以兼任几个领域。在治理简报列出已启用领域和主责，暂缓领域只在确有意义时记下启用信号。已有其他职责分工时沿用其名称并映射到根路由。

对齐摘要用几句话写清项目目标、本次范围、来源可靠的事实、未知项与暂定假设、建议的目录及取舍、完成判据。只有会实质改变本次生成结果的事项才需要先问。
