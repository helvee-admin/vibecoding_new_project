# 初始化与目录骨架

只问会改变本次交付的问题。先从当前会话、目标目录和用户指明的资料提取已知内容。阅读参考材料时区分观察、建议、原项目规则和用户已明确采用的规则。

| 主题 | 对齐内容 |
| --- | --- |
| 目标与价值 | 服务对象、要完成的任务、成功标准和明确非目标 |
| 范围与阶段 | 首个可交付结果、当前阶段、已确认的功能或工作边界 |
| 平台与输入 | 目标端、已有代码与资产、构建或交付位置、外部依赖 |
| 数据与运营 | 数据生命周期、隐私权限、商业约束，只有影响本次决策时才展开 |
| 协作 | 谁能决策，各领域怎么接手，资料和代码放哪，哪些写入已经授权 |

配合现有结构选择路径。以下是空项目的推荐命名。治理层是共享入口，领域按任务取舍。早期只有一两个领域时也可开始，等确有职责再扩展。

```text
AGENTS.md
docs/
  README.md
  governance/
    current-brief.md
    decision-log.md
  <domain>/
    AGENTS.md
    current-brief.md
    decision-log.md
    <current-spec>.md
```

## 文件模板

| 文件 | 初次写入 | 后续维护 |
| --- | --- | --- |
| 根 `AGENTS.md` | 项目目标与阶段边界，事实、假设及授权规则，读取顺序和文件归属，哪些事项要交决策人 | 只在协作规则、路由或长期边界改变时更新 |
| `docs/README.md` | 项目资料的入口和读法，启用领域及跨域或跨平台入口 | 路径或职责变化时更新，链接现行资料 |
| 治理 `current-brief.md` | 当前阶段、已知事实、关键约束、待定项和下一个行动 | 原位更新状态，链接关键决定或阶段收尾 |
| 治理 `decision-log.md` | 已确认的跨领域和长期约束 | 记录编号、日期、决定人或确认来源、结论、理由、影响范围和状态。被替换的决定标注替代编号 |
| 领域 `AGENTS.md` | 本领域职责、必读入口、判断标准、读写边界和交接条件 | 新规则归位。项目公共规则由根规则维护 |
| 领域简报与决定日志 | 领域当前状态及仅在该领域有效的确认。全局决定只写引用和本地影响 | 原位更新状态。判断应采用哪个规范时链接到现行条目 |
| 领域规范 | 当前有效的要求、约束、流程和必要的验收条件 | 同步受影响规则。尚未定稿的选项另标待定或另放草案 |

范围对齐可只用几行。写明目标、这轮交付及边界、已知与待定、计划的入口、什么算完成。没有确认过的决定时，写明该日志暂时无已确认事项，别为了填齐结构虚构编号或结论。核心规范还没有内容时，先从简报或索引指向已有资料，等规则确定后再增设文件。
