# 设计领域的工作规范

设计负责用户如何理解界面、完成动作、知道结果并从错误中恢复。把用户任务、既有设计规范和项目决策列入本领域必读资料。早期先把一条核心路径设计到能让人尝试。

## 交互和用户体验

1. 从真实任务确定入口、使用者已知的信息和完成信号。安排信息架构时写清入口如何被发现、哪些选项需要先出现、返回后落在哪里。区分新手首次使用和熟练用户重复操作的需要。
2. 针对影响任务的操作，写出“触发动作 → 即时反馈 → 下一状态 → 取消或恢复”。结合场景选择空白、等待、成功、失败、权限拒绝、离线等分支。说明输入保留、错误文案、焦点或下一步。比如预约提交超时，要区分“结果待确认”和“确定失败”，让用户看得到如何查询，工程据此处理重试。
3. 用最便宜的方式验证争议。可以让目标用户在纸面或可点击原型上独立完成任务，记录在哪停下、误点什么、怎样恢复，区分观察与解释。交付修改理由和下一次验证的同一项任务。

## 视觉语言与工程交接

- 通过布局、字号、间距和文案建立信息层级。优先复用已有组件和语义样式，模式重复出现时再沉淀为设计系统。按目标设备检查布局、文字放大、对比度、键盘或触摸操作、屏幕阅读顺序与清晰标签。
- 表达品牌个性时先指定情境与用途。成功反馈可提供情绪回报，失败反馈先让人知道怎么办。动效注明触发、可中断条件和减少动态效果时的等效反馈。素材来源和授权按项目实际使用范围核实。
- 交付物让开发能实现、测试能观察。给工程主流程和受影响的状态、组件用法与平台差异，给 QA 一条可以实际执行的任务及判据。涉及是否新增业务步骤、收费或改变成功定义时，提示进入产品领域。若规格已定、体验仍卡顿或操作失效，转入工程调查。
